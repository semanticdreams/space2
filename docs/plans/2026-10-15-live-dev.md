# Live-dev Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a user-selected live-dev primary that explicitly refreshes a verified checkout-scoped app after validated edits, with local-only checkpoints until authorized wrap-up.

**Architecture:** Keep the existing reload transaction, make watching optional, and place remote control and deferred operation tracking in one process-lifetime Fennel coordinator. Add private native startup provenance and a Linux lifecycle CLI. Reuse fast-dev's existing wrap-up skill and observational reviewer.

**Tech Stack:** C++17/sol2, Fennel/Lua, native callbacks, existing ZeroMQ remote control, Python standard library, pytest, CTest, OpenCode Markdown agents/skills.

## Global Constraints

- Linux first.
- Scope instance discovery and actions to the current checkout/worktree.
- Ask the user to select an instance when more than one matching app exists.
- Automatically start a missing app using normal user data/settings.
- Never request confirmation for start, reload, rebuild, restart, or transient state loss.
- Explicitly trigger broad app-root reload after coherent validated changes; no filesystem watching in live-dev mode.
- Rebuild/restart for native changes; restart for changes to preserved reload/control infrastructure.
- Keep direct edits and local commits on `live-dev/<topic>`; no publishing until explicit wrap-up authorization.
- Keep `supervisor` as the default primary and preserve unrelated agent boundaries.
- No legacy-instance compatibility or migration machinery.

| `.opencode/agents/live-dev.md` | Direct editing and validated refresh loop, local-only checkpoints |
| Existing wrap-up skill/reviewer | Shared authorized integration workflow |

The coordinator owns RC, controller, native callback IDs and registry record.
The app root borrows inspection references; it never drops these resources.
The outer process startup owns the coordinator and finalizes it once.

## Validation Conventions

- Build before runtime validation when native/bootstrap changed or the binary
  is stale: `make build`, explicit tool timeout `14400000` ms. After CMake
  edits: `make cmake`, timeout `600000` ms, then build.
- For direct Space commands use absolute `SPACE_ASSETS_PATH=$(pwd)/assets`,
  both `FENNEL_PATH` and `FENNEL_MACRO_PATH` set to
  `$(pwd)/assets/lua/?.fnl;$(pwd)/assets/lua/?/init.fnl`,
  `SPACE_DISABLE_AUDIO=1`, `SKIP_KEYRING_TESTS=1`, and
  `XDG_DATA_HOME=/tmp/space/tests/xdg-data`.
- Fennel validation order: project-native compile check, constraints, focused
  tests. Full checks are `make fennel-check` then `make constraints`. For
  targeted checks use `tools.fennel-check:main -- --target files --file <path>`
  and `constraints.runner:main -- --target files --file <path>`.
- Inspect the nearest enclosing form for parser failures, simplify nesting,
  then rerun compile before constraints. No system Lua/Fennel validation.
- Production app launch must not inherit test-only settings from the CLI's
  own testing harness by accident; tests explicitly pass an isolated app env.
- Each task: write/run regression red, implement, validate green, report
  coverage rationale and constraint impact, independent reviewer, fix/review
  until pass, then commit. Implementers must leave changes uncommitted for
  the review gate. The supervisor commits only reviewed changes.
- All runtime tasks may mechanically maintain existing entries in
  `assets/lua/constraints/baseline-data.fnl` when source edits shift line-keyed
  identities/fingerprints, or remove eliminated entries. Advisor-confirmed Task
  1 evidence established this need. Prove unchanged or lower measures; never
  add accepted debt, raise allowances, broaden suppression, or change rules.
